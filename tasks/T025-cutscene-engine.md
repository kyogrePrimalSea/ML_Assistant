# T025 — Cutscene engine and the boosting cutscene

**Status:** Backlog

**Epic:** E04

## Objective

Build the data-driven cutscene player (spec §9) and one cutscene: the Model
archetype hero for the boosting family — a fit line forming as trees are added.

## Context

Spec §4 (Model hero: decision boundary or fit line forming), §9 (code-driven, played
live, data-driven, illustrative numbers, shared toy datasets, plays once ≤1.2s, no
loops, replay button, reduced motion → static end frame or ≤120ms fade), §10.7.
Hero data lives in each record's `slots.solves.hero` (see `docs/CONTENT_SCHEMA.md`).
GSAP is pre-installed.

## Dependencies

- T020

## Implementation Contract

### Outputs

- `app/src/cutscenes/CutscenePlayer.tsx`: given a hero spec, picks the scene
  component by `kind`, plays once on open, shows a replay button, honours
  `prefers-reduced-motion`, pauses when off-screen, has an accessible text
  description of what the scene shows.
- `app/src/cutscenes/scenes/BoostingFit.tsx`: SVG scene: Ames-like scatter (house
  size vs price, ~60 illustrative points from a committed JSON) and a step-function
  fit that improves over 4–6 boosting rounds; round counter; ends on the final fit.
- `content/cutscenes/boosting-fit.json` (illustrative data, committed; generated by
  a small script in `tools/` from scikit-learn's GradientBoostingRegressor on a
  synthetic Ames-like sample so the shape is real), copied into `public/data/` by
  the content build.
- Wire into the Solves slot: pages whose hero `kind` has a scene show it; others keep
  the placeholder.
- Tests: plays once, replay works, reduced motion shows the end frame.

## Acceptance Criteria

- [ ] Boosting pages show the cutscene in the hero area; ≤1.2s; reduced motion respected.
- [ ] Lint, tests, build, e2e pass.

## Verification

`cd app && npm run lint && npm test && npm run build && npm run e2e`
